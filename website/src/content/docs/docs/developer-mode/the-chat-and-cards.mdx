This page explains the project screen in Developer mode: the chat in the middle and the cards beside it.

<Screenshot id="dev-chat" alt="A project in Developer mode: the sidebar of projects and chats, Mayka's chat in the centre, and the cards on the right" />

## The chat

You talk to Mayka in the project's chat. Ask a question, ask for a change, or ask what is going on. A project can have several chats; **New chat** in the sidebar starts another.

When Mayka wants to do something, she shows it as a **card** in the chat: what she proposes and why, with a button to apply it and **Dismiss**. For example, a work order card offers **Create and start** or **Create as draft**. How many cards wait for you depends on the project's mode: see [Assists me or Builds everything](/docs/apps/assists-or-builds/).

Mayka's updates on the work appear in the chat as short lines, so you can follow along without opening anything.

## The cards

Beside the chat, small cards sum up the project. Each one opens its own page in the centre, with a way back to the chat.

- **Project**: the vision and how far each priority has come. Opens the [vision](/docs/apps/how-building-works/).
- **Plan**: the [plan mode](/docs/developer-mode/plan-mode/) switch, and the written plan when there is one.
- **Work orders**: what is running, waiting or done. Every work order and session, done ones too, and the project's work as a live graph.
- **Agents**: which agents are at work right now.
- **Preview**: the running app, and a way to open it in its own Commitarium window.
- **Sync** (on this computer) or **Linked repository** (on a server): keeping the code in step with your own copy. See [Syncing](/docs/your-own-code/syncing/).
- **Deployment** (on a server): putting the app online. See [Deploying](/docs/online/deploying/).

## Sessions

Besides work orders, you can start a **session**: a single agent you steer turn by turn, for small edits where a full work order would be too much.
