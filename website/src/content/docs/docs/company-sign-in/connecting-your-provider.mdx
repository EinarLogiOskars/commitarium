This page shows you how to connect the sign-in system your company already uses.

You need someone who can add applications in your company's provider, and a server with [a domain](/docs/online/your-domain/).

## The steps, for any provider

1. Open **Settings > Server > Company sign-in**. It shows the **sign-in address** to register: `https://sign-in.<your domain>/oauth2/callback`.
2. In your provider, add an application (or "client") for Commitarium, of the web kind, with that address as its redirect address.
3. Note its **issuer**, **client ID** and **client secret**.
4. Back in Settings, enter the **Issuer**, **Client ID** and **Client secret**, and choose **Connect**.

Commitarium checks that the provider answers before it keeps anything. A provider that doesn't answer is not saved.

<Screenshot id="sign-in-settings" alt="Settings, Server, Company sign-in: the sign-in address to register and the issuer, client ID and secret fields" />

Under **More**, you can change the **scopes** (by default `openid email profile`) and the **groups claim** (by default `groups`). Some providers need `groups` added to the scopes to send groups.

:::caution
Enter the client secret in Settings only. Never paste it into a chat. If you did, make a new secret in your provider.
:::

## Provider by provider

### Microsoft Entra ID

- In **App registrations**, choose **New registration**, single tenant, with a **Web** redirect URI: the sign-in address.
- Make a client secret under **Certificates & secrets**.
- The issuer is `https://login.microsoftonline.com/<tenant ID>/v2.0`.
- For groups, in **Token configuration**, choose **Add groups claim**. Entra lists groups by their object IDs, so use those IDs in an app's groups.

### Google Workspace

- In Google Cloud, set the **OAuth consent screen**'s user type to **Internal**. This matters: with External, any Google account in the world could sign in.
- Make an **OAuth client ID** of type **Web application**, with the sign-in address as redirect URI.
- The issuer is `https://accounts.google.com`.
- Google puts no groups in its tokens, so an app is open to anyone at the company.

### Okta

- Make an **OIDC Web application** with the sign-in address as its sign-in redirect URI.
- The issuer is `https://<your Okta domain>/oauth2/default`.
- For groups, add a groups claim to that authorization server, and add `groups` to the scopes under **More**.

### authentik

- Make an **OAuth2/OpenID provider** (confidential) and an application for it, with the redirect URI.
- The issuer is `https://<authentik's address>/application/o/<application slug>/`.
- Groups come in the profile scope already.

No authentik yet? Commitarium can [set it up on your server](/docs/company-sign-in/authentik/) and connect it for you.

### Keycloak

- Make a **confidential OpenID Connect client** in the realm, with the redirect URI.
- The issuer is `https://<Keycloak's address>/realms/<realm>`.
- For groups, add a **Group Membership** mapper with the token claim name `groups` and **Full group path** off.

### Pocket ID

- Make an **OIDC client** with the sign-in address as callback URL.
- The issuer is Pocket ID's own address.
- Add `groups` to the scopes under **More**.

### Another provider

Any provider that speaks OpenID Connect works. Look for the same pieces under its own names: a web application, its redirect address, the issuer, the client ID and the secret, and a groups claim.

## Choose groups for an app

On an app's **Deployment** page, with **Who can open it** set to **Company sign-in**, choose **Choose groups** and list them, separated by commas, such as `sales, finance`. With none, anyone at the company may open it.
